In diesem Demo-Video wird die Gestenerkennung des Backends demonstriert. Die `DEMO.sh`-Sequenz zeigt einen POST-Request an den Endpoint `/api/v1/gestures/process-video`, wobei eine aufgezeichnete Video-Datei (`video Kreisbewegung.mkv`) als Eingabe dient. Das Backend liest das Video frameweise mit OpenCV ein und verwendet MediaPipe Pose, um pro Frame Körper- bzw. Handlandmarks zu extrahieren. Aus den relevanten Landmark-Koordinaten (z. B. Handgelenk) wird eine Trajektorie über die Zeit aufgebaut.

Zur Stabilität werden die Rohkoordinaten geglättet (EMA-Smoothing) und nur ein kürzerer Pufferspeicher (Sliding buffer) geführt, damit kurze Ruckler kein falsches Erkennen verursachen. Anschließend analysiert die Erkennungslogik die Trajektorie: Für Kreiserkennung werden der gesamte Winkelumlauf (angular sweep) und die Streuung des Radius geprüft — ein echter Kreis zeigt großen Winkelfortschritt und relativ konstante Radiuswerte. Für Wischgesten (links/rechts/runter) prüft das System größere Verschiebungen in einer Achse innerhalb kurzer Zeit.

Wenn eine Geste erkannt wird, liefert das Backend ein JSON-Resultat wie `{"gestures": ["circle"], "frames_processed": 79}` an den Request. Im Live-Betrieb ist der Ablauf identisch, nur dass statt einer Datei der Kamera-Stream (Webcam) als Bildquelle dient. Frames werden kontinuierlich verarbeitet, Gesten sofort per WebSocket an verbundene Clients gebroadcastet und können die Benutzeroberfläche (z. B. ein Widget) steuern.

Für die Präsentation können die Teammitglieder das Video zeigen und auf folgende Punkte hinweisen: 1) die Anfrage an den API-Endpoint, 2) die Frame‑Verarbeitung mit Landmark‑Extraktion, 3) die Trajektorien‑Analyse (Smoothing, Buffer, Sweep/Radial-Checks) und 4) das Ausgabeformat (erkanntes Gesten-Array). Betonung: Live erkennt das System dasselbe, nur dass Bilder von der Kamera statt aus einer Datei kommen.
